**Subject: Update the post-login "Teams workspace setup" flow for the new RSC-based onboarding**

**Context:**
Previously, when a new admin logged in via Microsoft Teams, our backend automatically created a "Vaptfix" team + 4 channels + an admin-dashboard channel as part of the login flow. We've removed that auto-creation because it was the direct cause of the "Need admin approval" screen blocking external-tenant admins from logging in at all (those permissions required tenant admin consent).

Team/channel creation now happens through **RSC (Resource-Specific Consent)** instead: the admin has to install the VaptFix app directly into a Microsoft Teams team they own. No admin approval is needed for that step. Once installed, the same 5 channels + welcome message get created automatically on our backend — same result, different trigger.

**What this means for the frontend:**
The endpoint you already poll after login — `GET /api/admin/users/microsoft-teams/login-status/` — behaves the same way for existing/already-onboarded admins (returns `status: "ready"` with `teams_tab_url` once their team exists). But for a **brand-new admin who has never installed the app anywhere yet**, this endpoint will now return `status: "provisioning"` (with an empty `teams_tab_url`) **indefinitely** — there is no longer a background process that will ever finish creating a team on its own, because nothing gets created until the admin installs the app.

**Required change:**
In whatever component currently polls `login-status/` after Teams login (I understand it polls roughly every 3s for up to ~45s waiting for `status: "ready"`):

- If the poll window ends and status is still `"provisioning"` (i.e. it never flips to `"ready"`), stop polling and instead of showing an error/stuck spinner, show a call-to-action:

  > "Install VaptFix in Microsoft Teams to finish setup"
  > [Install in Teams] button

- That button should open this deep link (opens the Teams client directly to the app's install page):
  ```
  https://teams.microsoft.com/l/app/cd35fdf0-6f75-41e9-8b58-a713dd7b9aeb
  ```
  The admin picks a team there and installs it — our backend picks up from there automatically (channels + welcome message get created within a few seconds of install).

- Optional but recommended: after showing that CTA, you can keep silently polling `login-status/` in the background (e.g. every 10–15s) so that once the admin comes back from installing the app, the UI auto-updates to `status: "ready"` and shows the normal "Open your VaptFix Teams workspace" link — without the admin needing to refresh manually.

**No other API contracts changed** — request/response shapes for `login-status/`, `oauth-url/`, etc. are exactly the same as before; this is purely about handling the case where `status` never resolves to `"ready"` from login alone.
